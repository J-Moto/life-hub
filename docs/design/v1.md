## 1. What v1 is (and isn't)

**Is:** one private web page showing five things:
1. Today's calendar
2. TickTick **Today** list with checkboxes
3. A box to add a task to **Next**
4. Weekly habit percentages
5. A **Restart** button

**Isn't (later versions, not v1):** scrap pad, clickable flowcharts, project planner, smart devices, finances, n8n, NAS integration, phone app, notifications.

**Why it exists:** a portfolio project that shows real OAuth, security and testing work. It is not a productivity fix. The system already works without it.

**Hard rules (from Life Hub design notes):**
- Reads TickTick and Google Calendar. **Stores none of their data.** If the hub is deleted, nothing is lost.
- No streaks anywhere. Percentages only, with a ~70% target line.
- No notifications in v1. Few alerts, or they stop working.
- Nothing carries over as debt. Restart sends Today's leftover tasks back to Next.

## 2. Decisions (recommended answers)

### A. The Today list

| # | Question | Recommended answer |
|---|---|---|
| A1 | What counts as "Today"? | The TickTick **project named "Today"**, not TickTick's smart Today filter. Show its unfinished tasks in TickTick's sort order. |
| A2 | What if Today has more than 3 tasks? | Show them all, plus one quiet line: "4 tasks today, the system says 3 max." No red, no warning icon. |
| A3 | What does checking a box do? | Marks the task complete in TickTick. The row fades, and **Undo** shows for 5 seconds before the request is sent, so a mis-tap costs nothing. |
| A4 | Can I edit or reorder tasks here? | **No.** Editing stays in TickTick. v1 only reads and completes. |
| A5 | Show `JOB:` tasks differently? | Yes. A small "JOB" tag in front, with the prefix text hidden. |

### B. Add to Next

| # | Question | Recommended answer |
|---|---|---|
| B1 | What does the box do? | Creates a task in the **Next** project with the text exactly as typed. |
| B2 | Help with the first-step format? | Placeholder text: `open resume doc (done = 1 application submitted)`. A **JOB** toggle adds the `JOB:` prefix. No other validation. |
| B3 | Add to Today or Someday too? | **No.** Only Next. Today is chosen in the morning routine, and Someday ideas go in from chat. |

### C. Weekly habit %

| # | Question | Recommended answer |
|---|---|---|
| C1 | Which habits? | The three: Job action, Phone-free morning, 15-min home reset. Their IDs are **stored in config**, because the API habit list can leave some out. |
| C2 | What's a "week"? | **Monday–Sunday**, so the number is complete at the Sunday Reset. |
| C3 | How is % calculated? | Check-ins ÷ days so far this week (not ÷ 7, so Tuesday isn't "28%"). The full-week number also shows at the Sunday Reset. |
| C4 | How is it shown? | One bar per habit with a thin line at 70%. No streak counts, no flames, no red. |

### D. Restart

| # | Question | Recommended answer |
|---|---|---|
| D1 | What does Restart do? | (1) Moves every unfinished Today task back to **Next**, (2) adds **one Minimum task** to Today, (3) shows "The system is back on." |
| D2 | Which Minimum task? | One fixed line from config: `JOB: open job board, save 1 posting (done = 1 saved)`. You can change the text in config. |
| D3 | Confirmation? | One confirm tap: "Move 3 tasks to Next and start fresh?" |
| D4 | Delete anything? | **Never.** Restart only moves tasks. |

### E. Calendar

| # | Question | Recommended answer |
|---|---|---|
| E1 | Which calendars? | Primary plus any you list in config. Hidden duplicates (like the old Class Calendar) are left out. |
| E2 | What's shown? | Today's events as a time list. Work Block (10:30) highlighted. A "now" line. |
| E3 | Write to Calendar? | **Not in v1.** Read-only scope. Writing a "Hub" calendar for the Akimart is **v1.1** (see section 6). |

### F. Where it runs and who can open it

| # | Question | Recommended answer |
|---|---|---|
| F1 | Hosting? | **One Cloudflare Worker** serves the page (static assets), the `/api/*` routes and the cron. This replaces the earlier "Worker + Pages" idea: one thing to deploy, and one place to protect. |
| F2 | Address? | `hub.josephmoto.com` **if** josephmoto.com's DNS is on Cloudflare. Otherwise the `*.workers.dev` address. ❓ Check where the domain's DNS lives. |
| F3 | Who can open it? | Only you. **Cloudflare Access** (free Zero Trust plan), with a one-email policy. |
| F4 | Defense if Access is bypassed? | The Worker checks the `Cf-Access-Jwt-Assertion` header on every request and rejects anything without a valid token for your email. |
| F5 | Routes that change data? | `POST` only: complete, add, restart. They require the Access JWT and a same-origin check. |
| F6 | Which devices? | PC browser and phone browser. A layout for the desk display size, plus a phone layout. No installable app in v1. |

### G. Logins and tokens (the security-critical part, built by the top model)

| # | Question | Recommended answer |
|---|---|---|
| G1 | How do the hub's logins happen? | A one-time `/setup` page (behind Access) runs the OAuth "sign in with…" flow for TickTick and for Google. |
| G2 | Where are tokens kept? | **Workers KV, encrypted** with AES-GCM (WebCrypto). The encryption key is a **Worker secret**. This is the one deliberate exception to "stores no data." |
| G3 | Other secrets? | OAuth client IDs and secrets live in Worker secrets (`wrangler secret put`). Never in code, `wrangler.jsonc`, CLAUDE.md or chat. |
| G4 | Scopes? | TickTick: `tasks:read tasks:write`. Google: `calendar.readonly` only. |
| G5 | Refresh? | Google: a refresh token mints short-lived access tokens on demand. TickTick: use the token until it fails, then show a "Reconnect TickTick" banner. Handle rotating refresh tokens if TickTick sends them. |
| G6 | Logging? | Never log tokens, auth headers or full API responses. Log only status codes and timings. |
| G6b | OAuth callback safety? | `state` stored server-side, single-use with a 10-minute TTL, tied to a `__Host-` SameSite=Lax HttpOnly cookie **and** the Access email. Fixed `redirect_uri`, PKCE checked. This stops login CSRF, where an attacker links *their* account to your hub. (From the independent review.) |
| G6c | Two refreshes at once? | KV is eventually consistent, so two refreshes could race and lose a rotated token. Refresh goes through **one place only** (a single Durable Object, or cron-only refresh). On `invalid_grant`, re-read KV once before showing "Reconnect". (From the independent review.) |
| G7 | Local development? | Separate dev OAuth apps and a test TickTick account if possible. Dev secrets go in `.dev.vars`, which Claude is blocked from reading. |

### H. Data freshness and failure

| # | Question | Recommended answer |
|---|---|---|
| H1 | When is data fetched? | **Live, on page load and on the refresh button.** No stored cache. That keeps "stores no data" true. |
| H2 | What's the cron for? | An **hourly health check**: can it reach TickTick and Google, and is each token still valid? Results go to the Worker's logs only. |
| H3 | If TickTick or Google is down? | Show whatever loaded. A quiet banner: "TickTick didn't answer, tried 9:41." Retry with backoff. |
| H4 | If a token expired? | Banner with a **Reconnect** button that goes to `/setup`. |
| H5 | Rate limits? | At most 1 request per section per page load. Exponential backoff on 429. |

### I. Quality and safety gates

- Tests: Vitest with the Workers test pool. TickTick and Google are mocked, plus one optional live smoke test.
- Each feature is built test-first (Superpowers TDD skill).
- On every branch: `/code-review medium`. Before merge: `/code-review high` + `/security-review` (top model).
- On every pull request: gitleaks, osv-scanner, CodeQL, Dependabot, plus a CodeRabbit review (works because the repo is public).
- Done means: tests pass, typecheck passes, and the changed route was hit locally with `wrangler dev`.

## 3. API sketch

| Route | Method | Does |
|---|---|---|
| `/` | GET | Dashboard page |
| `/api/today` | GET | Calendar events + Today tasks + habit % in one response |
| `/api/tasks/:id/complete` | POST | Complete a Today task |
| `/api/next` | POST | Add a task to Next |
| `/api/restart` | POST | Move Today's leftovers to Next, add the Minimum task |
| `/setup` | GET | Connect or reconnect TickTick and Google |
| `/oauth/ticktick/callback`, `/oauth/google/callback` | GET | Finish OAuth (state + PKCE checked) |

Config (non-secret, in `wrangler.jsonc` vars or KV): project IDs for Today and Next, habit IDs, calendar IDs, Minimum task text, time zone `America/Indiana/Indianapolis`.

> Public-repo note: project, habit and calendar IDs aren't secrets, but keep them out of the repo anyway. Put them in Worker vars that aren't committed, or in KV.

## 5. Build order (each one a branch)

1. Skeleton: Worker + static page + Access JWT check + tests (no real APIs)
2. Token storage module (encrypt/decrypt in KV) + `/setup` + OAuth for Google
3. Calendar section
4. OAuth for TickTick + Today list (read)
5. Complete with undo
6. Add to Next
7. Habit %
8. Restart
9. Health-check cron + failure banners
10. Design polish (Impeccable) + accessibility pass

Steps 2 and 4 are security-critical: written by the top model, reviewed by `/security-review`.
